Ch 8 — Core Definitions (MUST KNOW)

Predicate (P)Boolean expression → T/F. Built from variables, comparisons, boolean fns, logical ops.
Clause (c)Single atomic boolean condition (no AND/OR inside). E.g. P=(a&&(b||c)) → clauses a,b,c.
Major clauseThe clause currently being tested.
Minor clausesAll other clauses in P.
DeterminationClause ci determines P if changing ci (others fixed) changes P.
Real-world fact: 88.5% of predicates have 1 clause, 9.5% have 2, very few ≥3 — but the logic is still tricky.
Determine ≠ flip P. "Determines" = ci has effect on P's outcome under current minors.

Ch 8 — Basic Coverage (PC, CC, CoC)

CritRequirement
PCEach predicate P must be T at least once and F at least once.
CCEach clause c must be T at least once and F at least once.
CoCTest every combination of clause T/F values.

CoC formula: n clauses → 2n tests. Strongest, but exponential — impractical at n≥4.

Trap: CC ⇏ PC and PC ⇏ CC. CC may be satisfied while P is always T (one clause dominates via short-circuit).

PC weakness: may ignore clauses (short-circuit, one clause dominates).

CC weakness: doesn't guarantee P ever changes value.

Ch 8 — Active Clause Coverage (ACC) — THE CORE

Idea: for each clause c, build tests where c determines P, then flip c (T then F).

Algorithm (per clause):

  1. Pick c as major; the rest are minors.
  2. Fix minors so that c determines P.
  3. Make 2 tests: one with c=T, one with c=F.
  4. Verify only c flips between the two tests (and that P responds per the variant).
VariantMinors across the 2 rowsP must flip?
GACCcan differNO
CACC ★can differYES
RACCmust be identicalYES (auto)

Strictness: PC < CC < GACC < CACC < RACC. RACC ≈ MC/DC (FAA DO-178B/C).

Exam default: when asked "which coverage?" → CACC (best strength/feasibility tradeoff, subsumes PC).
RACC may be infeasible — if no two rows exist with identical minors that flip P, RACC is impossible; fall back to CACC.

Ch 8 — Make a Clause Determine P (3 methods)

1. Logical reasoning: AND chain → other clauses = T; OR chain → other clauses = F.

2. Definitional (XOR): p_c = p(c=T) ⊕ p(c=F); solve p_c=T for the exact minor condition.

3. Truth table: find 2 rows where only ci changes AND P changes.

Ch 8 — Worked Pattern: P = a ∧ (b ∨ c)

Determining conditions:

  • a active when b∨c = T
  • b active when a = T, c = F
  • c active when a = T, b = F

Sample CACC test set (2 tests/clause = 6 max, often dedupable):

Thermostat (a∨(b∧c))∧d: CACC needs 6 tests (vs 16 for CoC).

Ch 8 — 2-clause Quick Reference

a ∧ b: a det when b=T; b det when a=T. CACC pairs a:(TT,FT), b:(TT,TF). RACC = CACC.

a ∨ b: a det when b=F; b det when a=F. CACC a:(TF,FF), b:(FT,FF).

a ⊕ b: every clause always determines. CACC/RACC for a:(TT,FT)+(TF,FF) (4 GACC pairs total: any row pair where a flips).

Pattern: AND → minors all T; OR → minors all F; XOR → minors irrelevant.

Ch 8 — Inactive Clause Coverage (ICC)

Opposite of ACC: minors fixed so that c does not affect P. Tests c's independence.

4 tests per clause: (c=T,P=T), (c=F,P=T), (c=T,P=F), (c=F,P=F).

Variants: GICC (minors can change), RICC (minors fixed).

Ch 8 — Source-Code Challenges (Ch 8.3)

Two practical problems:

1. Reachability: inputs must drive execution to the predicate's line. E.g. if ((a||(b&&c))&&d) — you must reach this if.

2. Controllability: clause values come from program state, not inputs directly. E.g. dTemp = pSet.getSetting(period,day,settings) — you must configure period/day/settings to force a clause T/F.

Infeasible test cases exist (e.g. a>b ∧ b>c ∧ c>a). Detecting infeasibility is undecidable → identify and ignore.

Ch 8 — Exam Traps & Memory Hooks

  • "Determines" ≠ "flips P". GACC only requires determination; CACC requires P to also flip.
  • Minor clauses may differ in GACC/CACC; only RACC forces them equal.
  • RACC ≈ MC/DC. CACC subsumes PC; GACC does not.
  • CC ⇏ PC and PC ⇏ CC — independent.
  • CoC = 2n, exponential. Single-clause predicate → PC=CC=GACC=CACC=RACC.
  • For XOR / parity, every clause always determines P.
  • RACC can be infeasible when no row pair has identical minors and flips P → fall back to CACC.
  • Logic testing fails in code: reachability + controllability. Infeasibility detection is undecidable.

When to use what: 1 clause → PC; 2–3 → CoC; ≥4 → CACC. Avionics/safety → RACC.

Memory hook: "Pick major → fix minors so it determines → flip major and test."

Ch 9 — Exam Traps

  • PDC subsumes TSC (every production uses every terminal at least once eventually).
  • TSC ≡ Node Coverage; PDC ≡ Edge Coverage. Memorize this bridge.
  • DC (all derivations) is essentially infinite for recursive grammars — never the answer to "best criterion".
  • Mutation kills are per test: a test kills m iff output differs.
  • Equivalent mutant: cannot be killed; reduces achievable mutation score below 100%.
  • Valid mutants test extra valid inputs, not "wrong" ones — they still satisfy the grammar.
  • Invalid mutants test robustness: software must reject/handle them gracefully.
  • "Schema" = grammar + constraints (XML). Pure BNF doesn't enforce semantic constraints.

Refresh — Graph Worked Numbers

Hierarchy: CPC ⊃ PPC ⊃ EPC ⊃ EC ⊃ NC. PPC ⊉ EPC due to self-loops (n→n is in EPC but not a simple/prime path).

Why does EC subsume NC? path of length ≤ 1 covers length-0 (nodes) when every node has an out-edge AND a length-1 subpath exists between length-0 nodes.

Round-trip vs simple/prime:

  • Round-trip path: simple path with first = last (loop). PP-loop coverage handles loops 0/1/>1.
  • Prime path = maximal simple path; can't be extended.

Touring strength: Direct > Sidetrip > Detour. If direct infeasible, try sidetrip, then detour. Skip if all infeasible.

Best practical criterion: PPC. Real industry: branch (EC).

Ch 9 — Grammar-Based / Syntax Testing

Core idea: use a grammar of valid inputs to generate tests, and break it to produce invalid tests.

2 goals: cover valid syntax + break syntax (invalid tests).

Input domains: goal (should accept) ⊇ specified (spec) ⊇ implemented (code accepts). Bugs live in the mismatches.

Grammar types: Regex (simple patterns) · BNF (Backus-Naur Form, expressive) · XML+Schema (grammar + constraints).

Ch 9 — Grammar Structure (BNF)

Terminalliteral symbol that appears in final string (e.g. "deposit", digits).
Non-terminalvariable/placeholder, expanded by rules (e.g. <action>).
Production rule::= line; how to expand a non-terminal (alternatives via |).
Start symbolentry point of derivation.
<txn>    ::= <action> <account> <amount>
<action> ::= "deposit" | "withdraw"
<account>::= "checking" | "savings"
<amount> ::= <digit> <amount> | <digit>
<digit>  ::= "0" | "1" | … | "9"

Sample derivation: <txn> ⇒ "deposit" "savings" "50".

Ch 9 — Coverage Criteria

CritRequirementBound
TSCEvery terminal symbol used at least once#terminals
PDCEvery production rule used at least once#productions

PDC subsumes TSC. Grammar ↔ graph: PDC ≡ EC (edge coverage), TSC ≡ NC (node coverage). DC ≈ all paths — usually impractical.

Stream grammar: 13 TSC tests, 18 PDC tests, ~2×10⁹ DC tests.

Ch 9 — Mutation Testing

Ground stringvalid string from grammar.
Mutation operatorrule that modifies a string.
Mutantmodified version (valid or invalid).
Kill mutanttest t kills mutant m if output(orig) ≠ output(m).
Mutation scorefraction of mutants killed.

Criteria:

  • MC (Mutation Coverage): kill every mutant.
  • MOC (Mutation Operator Coverage): use each operator at least once.
  • MPC (Mutation Production Coverage): mutate every production rule that the operator can apply to.
Big picture: valid strings → correctness; invalid strings → robustness; mutants → fault detection.
One-liner: "Grammar defines inputs → tests are strings → mutation breaks them to expose bugs."

Ch 9 — Mutation Examples (Bank Stream)

Ground strings (valid):

G 26 08.01.90
B 22 06.27.94

Valid mutants (still in grammar):

B 26 08.01.90    (changed action G→B)
B 45 06.27.94    (changed amount 22→45)

Invalid mutants (break grammar):

7 26 08.01.90    (action must be G or B)
B 22 06.27.1     (date format wrong)

Common mutation operator types: replace terminal · swap order · drop symbol · duplicate · insert garbage · break recursion bound.

Equivalent mutant problem: mutant whose output is identical to original on every input — cannot be killed. Detection is undecidable.

Refresh — Ch 5 Criteria-Based Design

4 structures for modeling SW: Input Space (Ch 6) · Graphs (Ch 7) · Logic (Ch 8) · Syntax (Ch 9).

Test Requirement (TR): a specific element a test must satisfy. Coverage Criterion: rule producing TRs.

Coverage Level = #TR satisfied / #TR total.

Infeasible TR: no test can satisfy it (e.g. dead code). Detection is undecidable → 100% coverage rarely possible.

Subsumption: C₁ ⊃ C₂ if every C₁ test set also satisfies C₂. Subsumption ≠ better fault detection.

Recognizers > Generators in industry — recognizing tests is much easier than generating them.
